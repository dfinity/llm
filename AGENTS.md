# AGENTS.md

Libraries (Rust `ic-llm`, Motoko `mo:llm`) and example agents for using the LLM canister on the Internet Computer.

## Tooling

Tool versions are pinned in `mise.toml` (Rust 1.94.0, Node 22, pnpm 10.9.0, ic-mops 2.19.2). Install [mise](https://mise.jdx.dev/) and run `mise install`, or match those versions manually. `mise.toml` adds `./node_modules/.bin` to `PATH`. CI uses `jdx/mise-action` to provision these tools.

## Build, test, lint, format

Rust library (run in `rust/`):
- Test: `cargo test`
- Lint: `cargo clippy --all-targets --all-features -- -D warnings` (warnings fail CI)
- Format check: `cargo fmt -- --check`

Motoko library (run in `motoko/`):
- Test: `mops test`

These are the exact commands CI runs (`.github/workflows/tests.yml`). Motoko toolchain (`moc`) and mops dependencies are pinned in `motoko/mops.toml`.

## Layout

- `rust/` — the `ic-llm` Rust library crate.
- `motoko/` — the `mo:llm` Motoko package (`src/`, `test/`).
- `examples/quickstart-agent-rust`, `examples/quickstart-agent-motoko` — standalone example agents (canister backend + Vite/pnpm frontend), each with its own build config.

## Conventions & gotchas

- PR titles must follow Conventional Commits and are enforced by CI (`.github/workflows/conventional-commits.yml`). Allowed types: `feat`, `fix`, `chore`, `build`, `ci`, `docs`, `style`, `refactor`, `perf`, `test`; optional `(scope)` and `!` for breaking changes.
- `examples/quickstart-agent-rust/src/frontend/src/bindings` is generated by `just generate` (icp-bindgen); do not hand-edit.
- Not committed (see `.gitignore`): `target`, `node_modules`, `.dfx`, `.icp/cache`.
- The example agents depend on the pulled LLM canister `w36hm-eqaaa-aaaal-qr76a-cai` (see each `dfx.json` / `icp.yaml`).
